# Sable v1.0.0-alpha.1

An early native Windows PDF reader, ported from NightPDF with WinUI 3,
PDFium and the original night filters. This is a preview for testing.

## In this preview

- PDFs in tabs, with thumbnails, page labels and password prompts.
- Text selection/copy, Find, outlines, links and attachment saving.
- View rotation, hand panning, scroll/spread layouts and presentation mode.
- Two-finger trackpad scrolling and pinch zoom, with sharp PDF rendering.
- A command bar, a grouped All tools panel and a quick-tools strip.
- Document properties and Save a Copy, including unsaved edits.
- Comments: notes, highlight, underline and strikethrough, text boxes
  (including Hindi and Bengali shaping), freehand drawing, rectangles,
  ellipses, lines and arrows, and image stamps, each editable and removable.
- Form filling for text, check box, radio, combo and list fields.
- Fill & Sign: text, check marks and typed or drawn signatures.
- Organize pages (reorder, rotate, delete, insert, extract), Combine files
  and Export pages as images or text.
- Read Aloud with the Windows voices, speed and voice choice.
- Windows print preview and original-color printing.
- General, Shortcuts and About pages in Settings, and Obsidian (AMOLED).
- A music pane for Spotify and Apple Music sessions exposed by Windows.
- Windows contrast themes, named controls for screen readers, and the
  current page's text for Narrator.

## Downloads and running

Choose the x64 ZIP for Intel/AMD Windows PCs, or the ARM64 ZIP for Windows
on ARM. Extract the entire folder, then run Sable.exe. Keep the DLLs,
resources, assets, styles and language folders beside it.

Sable needs Microsoft's Windows App Runtime 2.5 or newer for the same
architecture. Many PCs already have it from other apps. If yours doesn't,
Sable says so when it starts and offers to open Microsoft's download page
(https://learn.microsoft.com/windows/apps/windows-app-sdk/downloads).
Install the latest 2.x runtime for x64 or ARM64 from there; it doesn't
need administrator rights. Then start Sable again.

There is no installer, file-association registration or automatic updater
in this preview. Once per start Sable asks GitHub whether a newer release
is out and shows a link if one is; it sends nothing but the request and
never downloads anything. Turn it off with Check for updates in Settings >
General. Settings and logs use the normal Sable application-data
folders. Closing and replacing the extracted app folder updates the app.
Keep the old folder until the new one has been checked.

This preview isn't code-signed. Windows SmartScreen may say "Windows
protected your PC" the first time Sable.exe runs: choose More info, then
Run anyway, if you got the ZIP from the release page and its hash matches
SHA256SUMS.txt. If Windows blocks files from the downloaded ZIP, open the
ZIP's Properties, tick Unblock and extract it again.

SHA256SUMS.txt lists the archive hashes. Each ZIP also has a manifest with
file hashes and source provenance; the source ZIP includes the build and
dependency-fetch scripts. A filename containing `-local-` is a local review
candidate, not a release built from a tag.

## Validation and known limitations

At the release commit, 822 x64 Debug tests pass and Debug and Release
builds for x64 and ARM64 have no warnings. The native probes drive the
real reader through tabs, layout, gestures, selection, Find, comments,
forms, Fill & Sign, organize, combine, export, Read Aloud, printing and
the accessibility audit. In the last 12 November run 69 of 70 passed.
KeyboardInput failed because another app on the test PC owns
Ctrl+Alt+G; it sends that shortcut through Windows.
TEST_PLAN.md and READER_CHECKS.md record the detailed checks and limits.

The x64 portable ZIP starts from an extracted folder with spaces in its
path, opens a PDF and closes cleanly on a PC that has the Windows App
Runtime. The message for a missing runtime and a second machine are still
to be checked. ARM64 has been compiled but not run on an ARM64 device.

Saved edits are checked by reopening in Sable and in raw PDFium. Acrobat
shows saved markup, notes, form values and text boxes; it also shows its
own "Font Capture" error on any PDF, including Adobe's own templates, so
that error isn't caused by Sable's files. Other colors, rotated pages and
printing from Acrobat remain unchecked.

Known limits in this preview:

- Signed or certified PDFs are refused for editing rather than risking the
  signature. Protected, shared and threaded annotation removal is refused.
- PDF layers can't be shown or hidden with the pinned PDFium API.
- Very tall document surfaces stop at the graphics limit with an error.
- Narrator reads the page text but not its formatting, selection or the
  on-screen position of each character.
- The build is unsigned, so SmartScreen warns on first run.

Desktop checks still open: physical touch, pen and trackpad input, monitor
changes with different scaling, real Spotify and Apple Music sessions, a
clean Windows PC without development tools or the Windows App Runtime
(including the missing-runtime message), Windows on ARM, a Narrator
listen-through, a contrast-theme look, and the update notice once a public
release exists. docs/RELEASING.md has the full list.

## Before publication

Keep this release as a draft until those desktop and clean-machine checks
have been recorded and the Windows App SDK license terms for the
bootstrapper DLL the ZIP still ships have been reviewed alongside Sable's
GPL-2.0-only license (THIRD_PARTY_NOTICES.md).
PDFium's license question (D10) was closed on 10 November. The release
workflow creates a draft prerelease and does not publish it automatically.
