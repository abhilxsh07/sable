# Sable v1.0.0-alpha.1

An early native Windows PDF reader, ported from NightPDF with WinUI 3,
PDFium and the original night filters. This is a preview for testing.

## In this preview

- PDFs in tabs, with thumbnails, page labels and password prompts.
- Text selection/copy, Find, outlines, links and attachment saving.
- View rotation, hand panning, scroll/spread layouts and presentation mode.
- Two-finger trackpad scrolling and pinch zoom, with sharp PDF rendering.
- Optional left/right page clicks to turn spreads in Page scrolling.
- Document properties and Save a Copy, including unsaved notes and markup.
- Notes, highlight, underline and strikethrough, with a Comments list,
  selection action menus, five highlight colors and safe removal.
- Text-note contents stay in Comments; their icons stay off the page,
  saved copies and print output. Clearing an existing note offers Delete.
- Windows print preview and original-color printing.
- Refined General, Shortcuts and About pages in Settings.
- Obsidian (AMOLED), with pure-black resting app surfaces and a saved choice.
- A music pane for Spotify and Apple Music sessions exposed by Windows.

## Downloads and running

Choose the x64 ZIP for Intel/AMD Windows PCs, or the ARM64 ZIP for Windows
on ARM. Extract the entire folder, then run Sable.exe. Keep the DLLs,
resources, assets, styles and language folders beside it. The ZIP includes
the Windows App SDK runtime; it is not a standalone EXE download.

There is no installer, file-association registration or automatic updater
in this preview. Settings and logs use the normal Sable application-data
folders. Closing and replacing the extracted app folder updates the app.
Keep the old folder until the new one has been checked.

SHA256SUMS.txt lists the archive hashes. Each ZIP also has a manifest with
file hashes and source provenance; the source ZIP includes the build and
dependency-fetch scripts. A filename containing `-local-` is a local review
candidate, not a release built from a tag.

## Validation and known limitations

The 26 October reader checks pass 556 tests in each x64 Debug and Release
suite. All four x64/ARM64 configurations build without warnings. Twelve
native reader workflows pass, including annotation actions, note editing,
selection, saving and printing. Saved text markup has normal appearance
streams before any viewer render; saved Text-note icons stay hidden in raw
PDFium rendering. Another PDF viewer has not been checked.

Earlier native checks covered the 1,000-page zoom regression. The full
tab/drop check stopped at denied storage-broker access; its earlier tab
cases and independent window checks passed. ARM64 has been compiled but
has not been run on an ARM64 machine.

The earlier reliability pass fixed a printing shutdown use-after-free, a
separate test-runner factory lifetime crash, and two zoom/navigation
transitions. Five shuffled full suites per normal configuration, three full
sanitizer suites and fifty focused printing repetitions passed then. The
sanitizer checked Sable's test-linked code; prebuilt dependencies were not
fully instrumented. The opt-in Windows PDF-driver check also passed in both
configurations for selected pages, sizes, colors, annotations and rotation;
the current Release driver check passes too.
See docs/TEST_PLAN.md for the test record and its limits.

Windows mouse input was checked for selection, popup Delete, note placement
and sidebar-only notes. Edited-copy saving passed the real Windows file
picker. The e01a5a2 package's Windows print preview passed portrait/landscape,
original colors, annotation print flags and cancellation. Custom ranges and
completed output through that dialog remain unverified; the desktop runner
could not keep focus in the PDF driver's output picker.

Physical touch/pen/trackpad input, overwrite confirmation, real Spotify/Apple
Music sessions, notification delivery and monitor changes still need desktop
sign-off. Local package startup does not replace a clean Windows machine
check. The source guide has the detailed checks in docs/READER_CHECKS.md and
docs/RELEASING.md.

Very tall document surfaces can reach the current graphics limit; the
reader shows an error rather than allocating an oversized surface. PDF
layers are deferred because the pinned public PDFium API lacks visibility
controls. Form filling, free text, ink, stamps, page editing and signing are
outside this preview. Protected, shared and threaded annotation removal is
refused. Existing stored markup shapes are preserved; new markup uses the
corrected line bands. Copies requiring unsafe attachment or annotation
rewrites are refused, keeping the original file untouched.

## Before publication

Keep this release as a draft until the desktop and clean-machine checks
have been recorded and the dependency-license review in
THIRD_PARTY_NOTICES.md has been resolved. In particular, the downloaded
PDFium license bundle contains Apache-2.0 text and the Windows runtime
packages supply Microsoft Software License Terms. Bundling those notices
does not resolve the distribution question. The release workflow creates
a draft prerelease and does not publish it automatically.
